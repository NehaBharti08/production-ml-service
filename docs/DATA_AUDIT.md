# Data Audit
> **NOT A CREDIT DECISIONING SYSTEM.** This document reports an engineering data audit on a public research dataset. Nothing in it is validated for lending, and it must never be used to decide anyone's access to credit.
> Generated by `uv run mlservice data audit` from `reports/data_audit.json`. Do not edit by hand — regenerate it.
---

## Summary
The dataset survives the audit. It is genuinely hard, genuinely messy, and carries real time structure — which is what makes it worth operating a model on rather than merely fitting one. Four findings changed the pipeline:
1. **Leakage, demonstrated rather than asserted.** Training on 16 post-origination columns reaches **ROC-AUC 0.9983** against an honest ceiling near 0.7. Of the 80,312 loans with `recoveries > 0`, **100.00%** are defaults — recoveries is money clawed back *after* a default, so a non-zero value **is** the label.
2. **Right-censoring dominates the recent years.** 40.37% of loans are still unresolved, and the resolved fraction collapses with recency. Requiring the full term to have elapsed moves the positive rate from **0.1998 to 0.148062** — skipping the rule overstates default by 35% relative.
3. **The label leaked back in as a feature.** `loan_status` is the column the target is derived from, so it maps one-to-one onto it. It survived the first pass because the data dictionary describes it as a loan attribute — which it is, right up until you make it the label.
4. **The time column is a real date.** `issue_d` is an actual date, so the chronological split is correct by construction and needs no statistical argument that an ordering carries time signal.

## 3. Right-censoring — the most consequential rule
Resolution is a function of age. A loan issued in December 2018 has not had time to default, so its absence of default is **not evidence of repayment**. Treating it as a negative teaches the model that recent loans are safe — which is a fact about when the file was exported, not about lending.

|:--|--:|--:|--:|
| 2007 | 603 | 100.0% | 0.262 |
| 2008 | 2,393 | 100.0% | 0.2073 |
| 2009 | 5,281 | 100.0% | 0.1369 |
| 2010 | 12,537 | 100.0% | 0.1401 |
| 2011 | 21,721 | 100.0% | 0.1518 |
| 2012 | 53,367 | 100.0% | 0.162 |
| 2013 | 134,814 | 100.0% | 0.156 |
| 2014 | 235,629 | 94.7% | 0.1845 |
| 2015 | 421,095 | 89.2% | 0.2019 |
| 2016 | 434,407 | 67.5% | 0.2329 |

Resolution depends on age. The 2018 cohort is 11.4% resolved and its default rate FALLS, which is survivorship among fast resolvers rather than better lending. Requiring the full term to have elapsed moves the positive rate from 0.1998 to 0.1481 — skipping it overstates default by 35% relative.

**The rule:** `issue_d + term <= observation_end`, with the observation window ending 2018-12-01. Stated, not tuned — a cut chosen to make the numbers look better is exactly what this audit exists to prevent.

## 4. Leakage

### 4.1 Post-origination columns — demonstrated
Training on 16 post-origination columns reaches ROC-AUC 0.9983 against an honest ceiling near 0.70. Of the 80,312 loans with recoveries > 0, 100.00% are defaults — recoveries is money clawed back after a default, so a non-zero value IS the label.

31 columns are dropped for this reason. They are enumerated in `configs/base.yaml` rather than inferred, because a heuristic like *drop anything correlated with the target* would also drop legitimately predictive features and could not explain itself.

### 4.2 The label as a feature
`loan_status` perfectly predicts the target: **True**. It is the column the label is derived from.

This is worth dwelling on. It survived the first version of the pipeline because the leakage list was written from the data dictionary, which describes `loan_status` as a loan attribute — and it is one, right up until you make it the label. **Deriving a target creates a leak that did not exist before**, so a leakage list cannot be written once and trusted.

### 4.3 Unresolved is not negative
912,602 loans were dropped for having no terminal outcome:

| Status | Loans |
|:--|--:|
| Current | 878,317 |
| Late (31-120 days) | 21,467 |
| In Grace Period | 8,436 |
| Late (16-30 days) | 4,349 |

A loan 90 days late will *probably* charge off, but probably is not a label. Encoding the guess would bake an assumption into the ground truth where nobody could see it.

## 5. Missingness
150 columns have missing values; 44 are more than half missing and are dropped.

Two kinds of absence, and they are treated differently:

- **Structural** — Lending Club added fields over the years, so a column introduced in 2015 is null for every earlier loan. Under a chronological split that is a proxy for the era rather than the borrower, which is why anything above 50% missing is removed.
- **Informative** — `mths_since_recent_inq` is null precisely when there has been no recent credit inquiry. That is a fact about the borrower, and a good one. Median imputation alone would convert *never* into *typical*, so the feature pipeline carries a missingness indicator alongside every numeric column.

## 6. Constants and collinearity
**Constant:** `disbursement_method`, `policy_code` — one value for every row. Zero information, and each costs a field in the serving contract.

**Redundant:** `fico_range_high`, `funded_amnt`, `funded_amnt_inv`. `fico_range_low` and `fico_range_high` correlate at **exactly 1.0** — they are two ends of a fixed-width band, so one is the other plus a constant. `funded_amnt` sits at 0.9989 against `loan_amnt`, because on a funded loan the amount requested is the amount funded. Keeping both halves of each pair gives a linear model two identical columns to split a coefficient across, inflating its variance and making the weights unreadable.

**Derived:** `earliest_cr_line` becomes `credit_history_months` (median 175.0). As shipped it is a date with 691 distinct values; as a categorical it would explode into hundreds of rare dummies encoding the era. Measured against the loan's own issue date it becomes how long the borrower has had credit — a real risk feature, and era-invariant.

## 7. Is the problem genuinely hard?
An unconstrained decision tree is fitted deliberately, and the hope is that it does **badly**. The logic is inverted on purpose: a tree with no depth limit that still generalises would mean something is leaking.

| | |
|:--|:--|
| Train ROC-AUC | 1.0 |
| **Test ROC-AUC** | **0.5335** |
| Tree depth | 66 |
| Leaves | 45,210 |
| Alarm (above 0.95) | False |

It memorises the training set completely and retains almost nothing. That gap is the healthy result.

| `prevalence_constant` | 0.8529 | 0.000 | 0.1471 |

**`heuristic_int_rate` is the one that matters.** `int_rate` is not a raw borrower attribute — it is the price Lending Club set *after* running their own underwriting model. So this baseline asks whether a new model beats the incumbent lender's judgment using a number available free at origination. A trained model that cannot clear it has not earned its deployment, monitoring and retraining infrastructure.

## 9. The split
chronological split on issue_d, a real date column.

| Split | Rows | Positive rate | Ends |
|:--|--:|--:|:--|
| train | 389,353 | 0.147481 | 2014-12-01 |
| val | 120,790 | 0.151246 | 2015-06-01 |
| test | 162,236 | 0.147088 | 2015-12-01 |

Cut on **month boundaries** rather than row positions: loans issued in the same month share a credit policy and a macro environment, so slicing through a month puts near-siblings on both sides. The realised fractions are therefore approximate rather than exactly 60/20/20, and are reported rather than assumed.

> **Limitation.** member_id is null for every row, so repeat borrowers cannot be detected and may appear in both train and test. Held-out metrics are inflated to whatever extent repeat borrowing occurs.

## 10. Subgroups
US credit data legally **excludes** race, gender and marital status, so there are no protected attributes to slice on directly. Fair-lending practice uses geography and socioeconomic position as proxies instead — which is what disparate-impact analysis has always done — and that is what these are.

A disparity found here is not proof of discrimination. It is the signal that prompts someone to look.

**`addr_state`** — 51 levels, 47 with n ≥ 500.

**`emp_length`** — 12 levels, 12 with n ≥ 500.

**`home_ownership`** — 6 levels, 3 with n ≥ 500.

## What this means for the model
The ceiling is low and that is the point. A model that cannot be perfected is a model that must be carefully operated — monitored, gated, and rollback-tested — which is what the rest of this repository is about.

Concretely, Phase 2 must:

- report **PR-AUC** against the 0.148062 prevalence floor, never accuracy;
- clear `heuristic_int_rate` with **non-overlapping confidence intervals**, not merely a higher point estimate;
- report **calibration** alongside discrimination, because a probability that is acted on must mean what it says;
- report **subgroup performance openly**, including where it is unflattering.
